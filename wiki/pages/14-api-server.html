OpenAI 兼容 API

🛠️ 使用面 · 14/22

设计目标

vllm serve 启动的服务尽量贴近 OpenAI 官方 REST 规范， 使得几乎所有针对 OpenAI 写的 SDK / 工具（LangChain、LlamaIndex、OpenWebUI、AutoGen、CrewAI…） 都能直接接入。

主要 endpoint

路径方法用途
/v1/chat/completionsPOST聊天补全（含流式、工具调用、推理 reasoning）
/v1/completionsPOST传统 completion（无 chat template）
/v1/embeddingsPOST嵌入（模型需是 embedding 模型）
/v1/scorePOST打分 / rerank
/v1/audio/transcriptionsPOSTWhisper 等音频转写
/v1/modelsGET列模型 + LoRA 适配器
/metricsGETPrometheus 指标
/healthGET健康检查
/tokenize / /detokenizePOST调试与计费用的 tokenization

流式（SSE）

把请求体里的 "stream": true 打开，server 会逐 chunk 推送 data: {...} 行， 最后以 data: [DONE] 结束。客户端按行读取即可。

resp = client.chat.completions.create(
    model="...",
    messages=[{"role": "user", "content": "讲个笑话"}],
    stream=True,
)
for chunk in resp:
    d = chunk.choices[0].delta.content
    if d: print(d, end="", flush=True)

工具调用 / Function Calling

支持工具调用的模型（Llama-3.1+ tools、Qwen-2.5 tools、Hermes、Mistral…）可以这样用：

{
  "model": "...",
  "messages": [...],
  "tools": [{
    "type": "function",
    "function": {
      "name": "get_weather",
      "description": "查天气",
      "parameters": {
        "type": "object",
        "properties": {"city": {"type":"string"}},
        "required": ["city"]
      }
    }
  }],
  "tool_choice": "auto"
}

启动时需要选 parser：

vllm serve <model> \
  --enable-auto-tool-choice \
  --tool-call-parser hermes        # 也可以是 llama3_json / mistral / pythonic / ...

Reasoning 输出（DeepSeek-R1 风格）

对 "先思考，再回答" 的模型，可启用 reasoning parser， 让"思考"内容单独放在 reasoning_content 字段：

vllm serve deepseek-ai/DeepSeek-R1-Distill-Qwen-7B \
  --enable-reasoning \
  --reasoning-parser deepseek_r1

结构化输出

详见 采样与结构化输出。可以传 response_format / guided_json / guided_regex / guided_grammar / guided_choice。

鉴权

用 --api-key 启动，客户端就要带 Authorization: Bearer ...。 也支持文件里多 key（--api-key /path/to/keys.txt，按行）。

Prometheus 指标

/metrics 输出包括：

  • vllm:num_requests_running / vllm:num_requests_waiting
  • vllm:time_to_first_token_seconds（TTFT）
  • vllm:time_per_output_token_seconds（TPOT）
  • vllm:gpu_cache_usage_perc
  • vllm:prefix_cache_hit_rate
  • vllm:num_preemptions_total

路由 / 多副本

vLLM 自身不内置 LB。常见做法：

  • 用 --data-parallel-size N 起内部多副本；
  • 外部用 Nginx / Envoy / Kubernetes Service 做轮询；
  • 用 vLLM Production Stack 等社区项目做 KV 复用 / 路由感知。
