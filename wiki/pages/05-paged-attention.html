PagedAttention 原理

🧠 核心原理 · 5/22

为什么需要它

Transformer 自回归推理时，每生成一个 token，都要把当前 token 和全部历史 token的 Key/Value 一起做注意力。为避免重复计算，历史的 K/V 会被缓存下来，这就是 KV Cache。 它的大小约为：

2 × L × H × d × seq_len × num_layers × dtype_size

其中 L=batch、H=KV head 数、d=head dim。对 Llama-3-8B、seq_len=4096、fp16 而言， 单条请求的 KV 缓存就有几百 MB。

问题在于：每条请求的真实长度未知。传统做法是按 max_seq_len 预留连续内存， 导致大量浪费——论文测得只有 ~30% 的显存真正被有效利用。

核心思想：像 OS 那样分页

PagedAttention 把 KV 缓存切成固定大小的块（block），每个 block 容纳 block_size 个 token 的 K 与 V（默认 16）。一条 sequence 的若干 token 不必住在连续内存里， 而是由一张块表（block table）记录"逻辑块号 → 物理块号"的映射—— 就像虚拟内存的页表。

flowchart LR subgraph Seq[一条请求的逻辑视图] L0[逻辑块 0] L1[逻辑块 1] L2[逻辑块 2] end subgraph Pool[GPU 上的物理 KV Cache 池] P0[Phys #0] P5[Phys #5] P9[Phys #9] P3[Phys #3] P7[Phys #7] end L0 -- block_table[0]=5 --> P5 L1 -- block_table[1]=9 --> P9 L2 -- block_table[2]=3 --> P3

带来的三个好处

  1. 近零碎片：除了每条请求最后一个块可能"半满"，其余块都是满的。 实测有效利用率从 ~30% 提升到 ~96%。
  2. 动态增长：seq 边生成边按需追加新块，不需要预估长度。
  3. 跨 seq 共享 / Copy-on-Write：当多个 seq 共享同一段前缀（比如同一个 system prompt）， 它们的 block_table 前几项可以指向同一组物理块；只有写入时才复制。这正是 Prefix Caching 与 beam search / 并行采样高效实现的基础。

Attention kernel 怎么访问

普通 FlashAttention 假设 K/V 是连续的。PagedAttention 的 CUDA kernel 多了一个 block_table 输入，按 token 索引去查物理块，再以 warp / threadblock 为单位读入 SRAM 做 softmax。 源码入口：

  • csrc/attention/：自研的 paged attention 内核（V1 fallback 与 CPU 后端）。
  • vllm/attention/backends/（V0）/ vllm/v1/attention/backends/（V1）： 通过 backend selector 把请求映射到 FlashAttention 2/3、FlashInfer、Triton、XFormers 等实现。

简化的 prefix-share 数学不变：

Attention(Q, K, V) = softmax(Q · K^T / sqrt(d_k)) · V

只是 K、V 的物理读取按 block 拆开，再合并到同一个 softmax 归一化里。

📝 此处的 Q、K 已经经过 RoPE 旋转—— 位置信息在 attention 之前就被注入到向量里，因此 PagedAttention 内核无需感知位置。

block_size 怎么选

block_size 是个权衡：

  • 过小（如 4）：块表更大、kernel 控制流更多；
  • 过大（如 64）：尾部浪费更多、Prefix Cache 命中粒度变粗。

默认 16（FlashInfer 后端可能选 32 或 64）。一般不需要手动改，知道有这么个旋钮即可。

Copy-on-Write 的细节

当 beam search 或并行采样在某一步分叉，新分支需要从父分支"分出去"。vLLM 不复制整段 KV， 而是共享之前的物理块，仅当某个块还没满需要继续写入时才复制一份新块，再写入新 token。 这把多分支采样的显存开销压到接近"只多一条短尾巴"。
