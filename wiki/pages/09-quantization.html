量化

🚀 关键特性 · 9/22

"量化"是把 fp16/bf16 权重（有时也包括激活、KV）用更少比特表达。在 vLLM 中， 你不需要自己写量化代码——只要加载社区或厂商已量化好的 checkpoint， 再传一个 --quantization 即可。

支持方案对比

方案权重位宽激活KV典型场景
FP8(E4M3/E5M2)8 bitFP8FP8（可选）Hopper/H100、MI300、最少精度损失
INT8 SmoothQuant8 bitINT8—Ampere/A100、H100，吞吐取向
GPTQ4 bit（per-group）FP16—显存优先，社区量产
AWQ4 bit（per-group）FP16—显存优先，量化质量略好
AutoRound4/3/2 bitFP16—极致显存（精度需评估）
BitsAndBytes(QLoRA 友好)4 bit (NF4) / 8 bitFP16—研究 / 兼容性
Marlin / Machete4/8 bit (kernel)FP16—vLLM 内部高性能 GEMM 实现

命令行用法

# GPTQ 模型
vllm serve TheBloke/Llama-3-8B-Instruct-GPTQ --quantization gptq

# AWQ 模型
vllm serve TheBloke/Mistral-7B-Instruct-v0.2-AWQ --quantization awq

# 原始权重 + 在线 FP8 量化 (NVIDIA Hopper+)
vllm serve meta-llama/Llama-3.1-8B-Instruct --quantization fp8

# KV Cache 也用 FP8（与权重量化正交）
vllm serve <model> --kv-cache-dtype fp8_e4m3

大多数情况下 --quantization 可以省略，vLLM 会从模型的 config.json 里的 quantization_config 字段自动识别。

该选哪一种

  • H100 / MI300 集群：首选 FP8。精度几乎无损、有专门硬件指令、 可同时量化 weight + activation + KV，整机吞吐显著提升。
  • A100 / 老一代 GPU：选 AWQ 或 GPTQ 4-bit。 社区生态最丰富，Marlin/Machete 内核已很成熟。
  • 研究 / 兼容：BitsAndBytes（与 PEFT / LoRA 训练栈协同好）。
  • 显存极度紧张：AutoRound 3-bit / 2-bit，但需要自己评估 task 上的精度。

"量化哪里"决定了什么

量化对象主要省什么影响
权重显存显存随位宽缩减，延迟随后端 kernel 而定
激活计算（Tensor Core 用低精度乘）主要影响吞吐
KV Cache显存（按 token 累积）长上下文场景显著节省

精度评估

量化必须搭下游评估。常见做法：

  • 跑 lm-evaluation-harness 对比 fp16 与量化后的 baseline。
  • 关键业务集（自己的 prompt 集）做 A/B 离线评测。
  • 对 Mixture-of-Experts 模型，注意 expert routing 对低 bit 更敏感，必要时只量化非 MoE 层。

实现要点

  • vLLM 在 vllm/model_executor/layers/quantization/ 注册各类量化"线性层"。
  • 核心 GEMM 内核在 csrc/quantization/ 与 csrc/cutlass_extensions/ 下： Marlin、Machete、cutlass-based FP8、AWQ kernels…
  • KV Cache 量化由 kv_cache_dtype 控制，scale 因子由模型 config 或运行时统计获得。

常见坑

"加了量化反而变慢？"

有可能：4-bit GPTQ 在极小 batch + 短 seq 下，dequant 开销可能盖过 GEMM 收益。 量化收益在大 batch / 长序列 / 多并发下才明显。

"FP8 模型在 A100 上能跑吗？"

不能用 FP8 Tensor Core。需要选 fp16/bf16 或 AWQ/GPTQ 版。FP8 需要 Hopper 及以上。
