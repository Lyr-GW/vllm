抽象：Platform + Attention Backend

  • vllm/platforms/：每个硬件平台一个 Platform 类，决定默认 dtype、是否支持 cuda graph、 可用的 attention backend 等。
  • vllm/attention/backends/ / vllm/v1/attention/backends/： 每个 backend（FlashAttention2/3, FlashInfer, XFormers, Triton, ROCm, CPU, TPU…）一个实现。
  • 启动时通过 VLLM_ATTENTION_BACKEND 或自动选择。

插件化后端

不是所有硬件都进主仓——Gaudi、Spyre、Ascend 等通过插件包维护：

  • 装 pip install vllm-hpu（举例），它会通过 vLLM 的 plugin 机制注册一个新 Platform。
  • 主仓变化时各 plugin 同步迭代。

开发者文档：docs/design/plugin_system.md。

选硬件的几个 thumb rule

  • 新部署 + 长上下文 / 大模型：H100/H200/B200 + FP8，几乎是性价比最高路径。
  • 已有 A100 集群：用 AWQ / GPTQ + FA2，仍能跑得非常好。
  • AMD MI300X：单卡显存 192GB，跑 70B/100B+ 单卡可行；ROCm 生态正在快速追赶。
  • 纯 CPU 推理：Xeon + AMX 在小模型 / 离线后处理场景可行；不要拿来扛在线流量。
  • TPU：在 GCP 上吞吐价格比有时优于 NVIDIA，但生态更窄。

多硬件混合？

vLLM 默认不支持单实例里混不同硬件；要混合，通常做"前端路由 + 多实例"。
