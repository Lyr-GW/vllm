安装与环境

📖 入门 · 3/22

三种主流安装方式

1. pip（最常用）

pip install vllm

# 或指定版本
pip install "vllm==0.6.4"

# 或额外加上某些可选依赖
pip install "vllm[audio]"     # 多模态音频
pip install "vllm[video]"     # 多模态视频
pip install "vllm[tensorizer]" # tensorizer 加载
提示

pip 包默认基于当前 PyPI 上稳定的 PyTorch 构建。如果你想用自己的 PyTorch（例如 nightly 或 ROCm 版），见下面"基于已有 PyTorch 构建"。

2. 源码构建

git clone https://github.com/vllm-project/vllm.git
cd vllm
pip install -e . --no-build-isolation

构建系统由 setup.py + CMakeLists.txt + cmake/ 中的辅助脚本组成， 会编译 csrc/ 下的 CUDA / ROCm / CPU 算子。常见控制变量：

环境变量作用
VLLM_TARGET_DEVICEcuda / rocm / cpu / tpu / xpu / neuron
MAX_JOBS并行编译线程数，避免 OOM
NVCC_THREADS每个 nvcc 调用的线程数
CMAKE_BUILD_TYPERelease / RelWithDebInfo / Debug
TORCH_CUDA_ARCH_LIST显式指定 SM 架构，如 "8.0;8.6;9.0"

基于已有 PyTorch 构建

仓库提供 use_existing_torch.py，可在依赖里删除对 torch==X.Y.Z 的硬性约束， 方便你使用本地装好的 PyTorch：

python use_existing_torch.py
pip install -e . --no-build-isolation

3. Docker

docker/ 目录下有官方 Dockerfile（GPU、CPU、ROCm 等）。最简单的方式：

docker run --runtime nvidia --gpus all \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  -p 8000:8000 \
  --ipc=host \
  vllm/vllm-openai:latest \
  --model meta-llama/Llama-3.1-8B-Instruct

Python 依赖

关键依赖（节选自 requirements/）：

  • torch（版本随每个 vLLM release 锁定）
  • transformers、tokenizers、huggingface_hub
  • xformers（部分 backend）/ flashinfer-python
  • fastapi + uvicorn + aiohttp（OpenAI server）
  • ray（多机分布式）
  • outlines / xgrammar（结构化输出）

常见安装坑

编译时 OOM

nvcc 单文件可能吃掉 8-12GB 内存。把 MAX_JOBS 调小（如 MAX_JOBS=4）通常能解决。

CUDA driver 与 runtime 不匹配

vLLM 报 CUDA error: forward compatibility was attempted on non supported HW 时， 通常是 nvidia-smi 里的驱动版本低于 wheel 编译时的 CUDA 版本。升级驱动或换匹配的 wheel。

显存够，但启动 OOM

vLLM 默认会"占用 90%"的显存（--gpu-memory-utilization 0.9）来预分配 KV Cache。 如果你机器上还有别的进程，把它降到 0.8 或更低。

Linux 共享内存不足

容器里多进程模型并行会用到 /dev/shm；启动 docker 时务必加 --ipc=host 或 --shm-size=8g。

验证安装

python -c "import vllm; print(vllm.__version__)"
python -m vllm collect_env

collect_env 会打印 GPU、驱动、CUDA、PyTorch、关键依赖版本，是提 issue 必备。

装好之后，进入 快速上手 跑第一条请求。
