项目简介

📖 入门 · 1/22· 阅读约 6 分钟

vLLM（读作 vee-LLM）是一个面向大语言模型（LLM）的高性能 推理与服务库。它最初由加州大学伯克利分校 Sky Computing Lab 在 2023 年开源， 2024 年成为 PyTorch 基金会 托管项目。一句话定位：

Easy, fast, and cheap LLM serving for everyone.

它解决了什么问题

传统 LLM 推理系统在两件事上不够好：

  • KV Cache 内存碎片严重：每个请求的上下文长度不同、生成长度不同， 用连续内存预分配会浪费大量显存（论文实测有效利用率不到 30%）。
  • 批处理粒度太粗：传统"等齐再批"会让短请求被长请求拖累， GPU 时常处于"等输入"的空转。

vLLM 给出的两个核心答案是：

  1. PagedAttention—— 像操作系统给进程分配虚拟内存那样，按"块（block）"管理 KV 缓存， 显存利用率从 30% 量级提升到 96%+；
  2. Continuous Batching—— 以"iteration"为粒度调度新请求随时插入、完成请求随时退出， GPU 利用率显著提高。

核心能力一览

极致吞吐同模型下相对原生 HF/Transformers 实现可提升数倍。
显存友好PagedAttention + Prefix Caching 让长上下文几乎不浪费。
易用接口LLM(...).generate() 一行离线推理；vllm serve 一条命令起 OpenAI 兼容 HTTP 服务。
多硬件NVIDIA / AMD / Intel CPU&GPU / TPU / Gaudi / Spyre / Ascend …
多并行Tensor / Pipeline / Data / Expert / Sequence 并行齐全。
多模型无缝兼容主流 HuggingFace 权重，含 MoE、Embedding、多模态。
多算法Beam search、并行采样、投机解码、Guided/JSON 结构化输出、Tool calling。
多量化GPTQ / AWQ / AutoRound / FP8 / INT8 / INT4 / BitsAndBytes。

适合 / 不适合什么

非常适合：

  • 需要高吞吐对外提供 OpenAI 兼容服务（聊天、补全、嵌入、打分）；
  • 需要离线大批量推理（生成训练数据、合成评测）；
  • 多用户共享一个或多个 GPU 的场景；
  • 需要长上下文（32K~1M）且对显存敏感。

不那么适合：

  • 单条请求、极低 batch、对单次延迟做极致工程的场景（可考虑 TensorRT-LLM / SGLang 等横向对比）；
  • 训练（vLLM 不是训练框架；它只关心推理与服务）；
  • 需要在异构边缘设备上跑（vLLM 主要面向数据中心 GPU 和高端 CPU）。
