整体架构

📖 入门 · 2/22

本页用一张图 + 一组列表把 vLLM 的整体架构讲清楚，并解释 V0 与 V1 两套实现的差异。

三层入口

无论以哪种方式使用 vLLM，调用链最终都汇入同一个引擎核心。从用户视角看，有三种入口：

  1. 离线推理：在 Python 里直接构造 LLM(...) 对象，同步调用 generate() 或 chat()。
  2. 异步推理：AsyncLLM（V1） / AsyncLLMEngine（V0），返回异步迭代器，适合在自己的服务端嵌入。
  3. HTTP 服务：vllm serve 启动一个 FastAPI 进程，对外暴露 OpenAI 兼容 REST/SSE 接口。

V0 vs V1

V1 是 2025 年 1 月发布的架构级重写，目标是更干净、更快、更易扩展。要点：

  • 统一执行循环：prefill 与 decode 用同一个 execute_model 路径， chunked prefill 不再是特例。
  • 零开销 Prefix Caching：缓存命中检查的成本被压低到接近 0， 日常负载下默认开启不会变慢。
  • Process-isolated EngineCore：API 进程 ↔ 引擎进程之间用 ZMQ 通信， 避免 GIL 影响调度。
  • 整洁的 KV Cache 抽象：通过 kv_cache_interface.py 描述每层的需求， 支持 hybrid（如 Mamba+Attention 混合）。
  • 更现代的 torch.compile / CUDA Graph 集成：默认更激进， 详见 CUDA Graph & torch.compile。

V0 仍在仓库中保留以兼容老硬件 / 老路径，但新功能优先落在 V1，本 Wiki 也以 V1 为主线讲解。

建议的学习顺序

  1. 先看 安装 + 快速上手，跑通离线和在线两种用法。
  2. 读 PagedAttention 与 KV Cache 理解性能来源。
  3. 用 调度器 + 连续批处理 串起一次推理的全流程。
  4. 按需翻阅 量化、分布式、投机解码 等专题。
  5. 遇到问题查 FAQ，看不懂的英文术语翻 术语表。
