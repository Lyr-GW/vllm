关键指标

指标定义受谁影响
TTFT (Time To First Token)请求到达 → 收到第一个输出 token 的时间Prompt 长度、Prefix Cache 命中、调度排队
TPOT (Time Per Output Token)每个新 token 的平均时间（端到端）Decode kernel、batch 大小、KV 总量
ITL (Inter-Token Latency)连续两个 token 之间的间隔同上，但更细粒度
Throughput所有请求合计的 tokens/sec并发、Prefill 比例、量化、并行
Goodput满足 SLA 内的有效吞吐SLA + 上面所有

仓库自带基准脚本

benchmarks/ 目录提供常用脚本：

1. benchmark_throughput.py — 离线吞吐

python benchmarks/benchmark_throughput.py \
  --model meta-llama/Llama-3.1-8B-Instruct \
  --dataset-name sharegpt --dataset-path ShareGPT.json \
  --num-prompts 1000 --tensor-parallel-size 1

2. benchmark_serving.py — 在线压测

# 先在另一终端起 vllm serve ...
python benchmarks/benchmark_serving.py \
  --backend vllm --model meta-llama/Llama-3.1-8B-Instruct \
  --dataset-name sharegpt --dataset-path ShareGPT.json \
  --num-prompts 1000 --request-rate 16

--request-rate ∞（或 inf）表示尽量并发，测稳态。

3. benchmark_latency.py — 单/小批延迟

python benchmarks/benchmark_latency.py \
  --model <model> --batch-size 1 --input-len 512 --output-len 128

调优 checklist

先看 KV 占用

vllm:gpu_cache_usage_perc 长期 < 60%？说明 batch 没打满，或 prompt 短； 可加大 --max-num-seqs / --max-num-batched-tokens。

看抢占率

vllm:num_preemptions_total 飙升 → 资源不够，降并发或加量化。

看前缀命中

vllm:prefix_cache_hit_rate 低于 30%？检查 system prompt 是否一致； 确认 --enable-prefix-caching。

一般来说从下面 8 个旋钮按顺序尝试：

  1. 开 / 确认 --enable-chunked-prefill 与 --enable-prefix-caching。
  2. 加大 --max-num-seqs 与 --max-num-batched-tokens，直到 GPU 占用近 100%。
  3. 试 --kv-cache-dtype fp8_e4m3（H100/MI300+）。
  4. 试 --quantization fp8 / awq。
  5. 合理设置 --max-model-len，避免预留过多 KV。
  6. 加 TP / PP 并行；按 NVLink 拓扑选维度。
  7. 调 --gpu-memory-utilization，留少量富余给 fragmentation。
  8. 遇到长 prompt 用 --max-num-batched-tokens 控制 chunk 粒度。

Profiling

  • VLLM_TORCH_PROFILER_DIR=/tmp/prof vllm serve ... → torch.profiler 输出。
  • NVIDIA Nsight Systems / Compute（nsys profile）观察 kernel 时间线。
  • Python 侧：py-spy dump --pid <pid> 看是否被 GIL / IO 卡住。

对比基线

使用同模型 / 同 prompt 集对比：

  • HuggingFace transformers.generate()：基线，最慢；
  • TGI（Text Generation Inference）：HuggingFace 自己的服务；
  • TensorRT-LLM：NVIDIA 极致优化，但工程量大；
  • SGLang / lmdeploy：vLLM 的同代竞品；
  • llama.cpp：CPU/边缘场景。

核心是用同样的负载评测同样的指标——不要拿"单条 latency"对比"高并发 throughput"。
