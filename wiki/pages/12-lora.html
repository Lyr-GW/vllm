LoRA 多适配器

🚀 关键特性 · 12/22

LoRA 是什么

LoRA（Low-Rank Adaptation）只训练两个小矩阵 A ∈ R^{d×r}、B ∈ R^{r×d} （r 通常 8/16/32），推理时把它们叠加到基座权重上：

W' = W + (α/r) · B · A

因此一份基座可以挂多种 LoRA 适配器（领域、风格、人格、租户隔离）， 共享显存里那份巨大的基座权重，仅按 r 增加少量参数。

vLLM 的多 LoRA 调度

vLLM 支持同一 batch 内多个请求各自挂不同的 LoRA。它通过专门的 Punica 风格内核， 按 token 标签把矩阵乘"分配"到对应适配器，避免逐请求顺序处理。

启动与调用

vllm serve meta-llama/Llama-3.1-8B-Instruct \
  --enable-lora \
  --max-loras 4 \
  --max-lora-rank 32 \
  --lora-modules \
    sql=path/to/sql-lora \
    cn-styled=path/to/zh-style-lora

调用时通过 model 字段指定使用哪个适配器：

from openai import OpenAI
client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
client.chat.completions.create(
    model="sql",     # 名字来自 --lora-modules
    messages=[{"role": "user", "content": "把这段需求转成 SQL: ..."}],
)

也可以动态加载/卸载（避免重启服务）：

curl -X POST http://localhost:8000/v1/load_lora_adapter \
  -d '{"lora_name": "new", "lora_path": "/data/new-lora"}'

curl -X POST http://localhost:8000/v1/unload_lora_adapter \
  -d '{"lora_name": "new"}'

开启动态加载需要 --enable-lora-bias（如适用）与 VLLM_ALLOW_RUNTIME_LORA_UPDATING=True（按版本而异）。

关键参数

参数说明
--max-loras引擎可同时驻留的 LoRA 数（GPU 上的"slot"）
--max-lora-rank所有 LoRA 的 r 上限（统一以最大值分配 buffer）
--max-cpu-loras允许 CPU 内存里缓存的 LoRA 总数（命中后再换上 GPU）
--fully-sharded-loras结合 TP 时将 LoRA 也切分
--lora-dtypeauto / float16 / bfloat16 / float32

与量化、TP、长上下文的关系

  • 量化基座 + fp16 LoRA：可行，社区常用 QLoRA 训练即是这种思路。
  • TP：LoRA 矩阵也按 TP 切分，性能基本不下降。
  • 长上下文 + LoRA：与基座一致，PagedAttention 不受影响。

什么时候不要用

  • 需要改动 embedding 词表 / token 化的场景，应优先全参数微调。
  • "行为差异巨大"的多任务（比如代码 vs 多语对话）建议各起一个引擎，而非靠一份基座 + 多个 LoRA。

源码位置

  • vllm/lora/：LoRA 模型 / 请求注解 / 加载逻辑。
  • csrc/ 中的 Punica 风格 kernel（不同后端命名不一致）。
