投机解码

🚀 关键特性 · 11/22

动机

Decode 阶段是memory-bound：每生成一个 token 都得把整模型权重从 HBM 搬到 SRAM。 如果能"一次性生成多个 token"，单步收益就成倍提升。投机解码（Speculative Decoding）就是干这件事： 让一个便宜的 draft 模型预测后 N 个 token，然后让目标大模型一次性批量验证。

基本流程

sequenceDiagram participant D as Draft 模型(小) participant T as Target 模型(大) D->>D: 生成 k 个候选 token t1..tk D->>T: 把 [prompt, t1..tk] 一次前向 T-->>T: 对每个位置算自己的概率 Note over T: 从左到右逐个接受/拒绝 T-->>D: 接受 m 个 token(0 ≤ m ≤ k), 第 m+1 个用 T 的 token 覆盖

关键性质：接受/拒绝过程使用重要性采样， 保证最终分布与"完全用 target 自回归生成"完全等价——投机解码不损精度， 是无损加速。

vLLM 支持的算法

算法Draft 来源说明
N-gram从 prompt 中抽取常见 n-gram零额外参数，适合长重复模板
独立小模型另一个 LM（如 1B / 3B 同家族）通用最稳，需多放一份权重
Medusa主模型加多个"输出头"不需要单独模型，吞吐增益中等
EAGLE / EAGLE-3主模型 hidden state 上的轻量 draft net当下精度/吞吐最好的方案之一
MLPSpeculator多头 MLP 推测IBM 提出，简单

命令行示例

# 独立小模型
vllm serve meta-llama/Llama-3.1-70B-Instruct \
  --speculative-config '{
    "model": "meta-llama/Llama-3.2-1B-Instruct",
    "num_speculative_tokens": 5
  }'

# N-gram
vllm serve <model> \
  --speculative-config '{"method": "ngram", "num_speculative_tokens": 5, "prompt_lookup_max": 4}'

# EAGLE
vllm serve <target> \
  --speculative-config '{
    "method": "eagle",
    "model": "<eagle-head-checkpoint>",
    "num_speculative_tokens": 5
  }'

实际收益取决于"接受率"

记单步候选数 = k，接受率（每候选被采纳的概率）= α，则平均每步实际产出 1 + αk 个 token。但每步成本变成"draft 算力 + target 一次 k+1 长度的前向"。

所以投机解码并不总是赢：

  • α 低时（draft 与 target 风格差太多），可能负收益；
  • k 太大时，目标模型的"批"会变胖，单步反而慢；
  • 高并发 batch 下，target 本身已经在大批跑了，draft 引入的串行约束会限制吞吐。
经验值

通用对话：k=3~5，期望加速 1.3×~1.8×；编码 / 模板化输出：k=5~8，可见 2× 以上； 与同家族 1B 作 draft 通常优于跨家族；强烈建议先用 benchmark_serving.py 实测。

源码位置

  • V1：vllm/v1/spec_decode/（draft runner、proposer、verifier）。
  • EAGLE、Medusa 的特殊 head：vllm/model_executor/models/eagle*.py 等。

排障 checklist

  • 开关后吞吐反而下降 → 用 num_speculative_tokens=1 试，再逐步加。
  • 接受率长期低于 30% → 换更同源的 draft 模型；或改用 EAGLE。
  • 显存爆 → draft 模型也占显存，记得预留。
