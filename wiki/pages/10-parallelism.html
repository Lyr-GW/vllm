分布式与并行

🚀 关键特性 · 10/22

当单卡显存 / 算力扛不住一个模型，或单实例吞吐撑不住流量，就需要并行。 vLLM 提供 5 种正交的并行维度，可以组合：

缩写名称切分对象典型用途
TPTensor Parallelism每层权重矩阵按行/列切到不同 GPU单层算不下时，最常用
PPPipeline Parallelism不同层放到不同 GPU，流水推进跨节点扩展，避免 TP 跨机带宽瓶颈
DPData Parallelism整个引擎多副本，请求分流纯吞吐扩展
EPExpert ParallelismMoE 的不同 expert 放到不同 GPU大 MoE 模型（DeepSeek、Mixtral）
SPSequence / Context Parallelism同一条 sequence 的不同 token 分到不同 GPU超长上下文

Tensor Parallelism (TP)

把每个线性层的权重按维度切分。比如一个 [H, 4H] 的 FFN 权重， 在 TP=2 时分别放两张卡上各 [H, 2H]，激活做列切分 / 行切分组合， 最后用 all_reduce 同步。每一步需要一次或两次小通信。

vllm serve meta-llama/Llama-3.1-70B-Instruct --tensor-parallel-size 4

实践建议：

  • TP 通信走 NVLink / NVSwitch 时最优，跨 PCIe 性能会差很多。
  • TP size 必须能整除 attention head 数与 FFN 隐藏维。
  • vLLM 自带 Custom All-Reduce（csrc/custom_all_reduce.cu） 在小消息上比 NCCL 更快。

Pipeline Parallelism (PP)

把模型的 L 层切成 P 段，每段放一台/一组 GPU。请求像流水线一样穿过：

vllm serve <model> --tensor-parallel-size 8 --pipeline-parallel-size 4

关键点：

  • 跨机用 PP 比跨机用 TP 通信少（每条 seq 只在边界处传 activation）。
  • 有"气泡"问题——首尾时刻有部分 stage 空闲；vLLM 用microbatch 间交错调度缓解。

Data Parallelism (DP)

不是真正"分一个模型"——而是每张卡（或每组卡）跑一个完整引擎， 请求按 round-robin 或一致性 hash 分到不同副本。

vllm serve <model> --data-parallel-size 4
  • 简单、几乎零通信，吞吐线性扩展。
  • 缺点：单卡装不下大模型时没法用。
  • 常与 TP 组合：例如 8 卡 → 2×DP × 4×TP。

Expert Parallelism (EP)

MoE 模型（如 Mixtral 8x7B、DeepSeek-V3）每个 token 只激活 1~2 个 expert。 把不同 expert 放到不同 GPU，token 路由后做 all-to-all 通信。

vllm serve deepseek-ai/DeepSeek-V3 \
  --tensor-parallel-size 8 \
  --enable-expert-parallel \
  --expert-parallel-size 8

EP 对 all-to-all 带宽要求很高，NVLink + InfiniBand 是常见组合。 vLLM 也提供 fused MoE kernel（csrc/moe/）压低非通信开销。

Sequence / Context Parallelism (SP)

超长上下文（如 1M）下，单卡放不下整条 sequence 的 KV，需要把 token 维度切开。 具体实现因 backend 而异，详见 官方文档：Context Parallel Deployment。

组合：一个 70B 上 8 卡的典型配置

vllm serve meta-llama/Llama-3.1-70B-Instruct \
  --tensor-parallel-size 4 \
  --pipeline-parallel-size 2 \
  --max-model-len 32768 \
  --gpu-memory-utilization 0.92

= 4 卡 TP × 2 段 PP = 8 卡，权重切到 4 份，每段两卡跑半个模型。

多机部署

vLLM 跨机依赖 Ray：

  1. 主节点：ray start --head --port=6379
  2. 从节点：ray start --address=<head-ip>:6379
  3. 主节点：vllm serve <model> --tensor-parallel-size 16 --pipeline-parallel-size 2

Ray 把 worker 进程自动调度到合适的机器；也可以用 --distributed-executor-backend mp 在单机用 multiprocessing 替代 Ray。

排障 checklist

  • NCCL 卡死？设 NCCL_DEBUG=INFO、检查 IB/RoCE。
  • P2P 失败？某些云上虚拟 GPU 不支持 P2P，需要 NCCL_P2P_DISABLE=1。
  • 跨机带宽差？优先 PP > TP；如果带宽实在低，DP + 路由更稳。
  • 启动慢？关掉 --enforce-eager 之外的不必要 CUDA Graph 捕获。

继续：投机解码——以小模型预测大模型，减少 decode 步数。
