贡献指南

📚 参考 · 20/22

欢迎给 vLLM 提 PR！下面把流程梳理一遍。

1. 开发环境

git clone https://github.com/vllm-project/vllm.git
cd vllm
pip install -e . --no-build-isolation
pip install -r requirements/dev.txt
pre-commit install

项目使用一组代码规范工具，pre-commit 会在每次提交前自动跑：

  • yapf / ruff：Python 风格
  • clang-format：C++/CUDA 风格（见 .clang-format）
  • shellcheck：Shell 脚本
  • markdownlint：Markdown 文档
  • codespell / mypy：拼写 / 类型检查（部分目录）

2. DCO 签名

vLLM 要求每个 commit 包含一个 Developer Certificate of Origin 签名（不是 CLA）：

git commit -s -m "feat: ..."   # 会自动加 "Signed-off-by: 你 <email>"

3. 提 PR

  1. 从 main 切分支：git checkout -b feat/awesome。
  2. 本地跑相关单元测试：pytest tests/path/to/your/test.py。
  3. 用 快速上手 里的命令做一次 smoke：跑通离线 / 在线请求。
  4. PR 标题用 [Feature] / [Bugfix] / [Doc] 等前缀，清楚描述动机与影响范围。
  5. 主动指明会触发的 CI label（如 ci/build、kernel/marlin），加速调度。

4. CI 系统

vLLM 用 Buildkite 作为主 CI（.buildkite/），覆盖：

  • 多 GPU 测试（A100、L4 等）
  • 多硬件平台（CPU、ROCm 等通过插件 fork 单独跑）
  • 构建 wheels / docker images

对 contributor 不可见的私有 CI 部分由维护者跑。提交前用 tools/ci/... 里的脚本本地检查。

5. 加新模型

典型步骤：

  1. 在 vllm/model_executor/models/ 新建 my_model.py， 继承现有 LlamaForCausalLM 或写新的 forward。
  2. 实现 load_weights、compute_logits 等方法， 与 HuggingFace 的权重命名对齐。
  3. 在 vllm/model_executor/models/registry.py 注册。
  4. 添加单测：tests/models/test_my_model.py。
  5. 更新 docs/models/supported_models.md。

详见 docs/contributing/model/ 下的子目录。

6. 加新硬件

通常作为插件包而非主仓 PR，参考 Gaudi / Spyre / Ascend 的 plugin 仓库。 插件机制见 docs/design/plugin_system.md。

7. 写文档

文档源在 docs/，用 mkdocs-material。本地：

pip install -r requirements/docs.txt
mkdocs serve

8. 行为准则与协议

  • 遵循 CODE_OF_CONDUCT.md。
  • 代码遵循 Apache-2.0。
  • 安全问题请通过 GitHub Security Advisory 私下报告（见 SECURITY.md）。

祝你 PR 顺利 👋。
